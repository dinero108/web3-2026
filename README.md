## 새 기능
이메일 회원가입·로그인·로그아웃, 비밀번호 재설정, Supabase 계정별 비공개 기록 저장을 구현했습니다. 서비스 이용에는 회원가입·이메일 인증·로그인이 필수입니다. 비로그인 상태에서는 대시보드, 상세 페이지, SBT 배포 화면을 열 수 없습니다. 로그아웃하면 즉시 로그인 화면으로 돌아갑니다. 기존 게스트 기록은 새 버전 실행 시 해당 브라우저에서 삭제되며 계정 가져오기 기능은 제공하지 않습니다.

Resend 발신 도메인 auth.dinero.kr 인증과 Supabase SMTP 연결을 완료했습니다(2026-11-02). 발신자는 패스폴리오 <noreply@auth.dinero.kr>입니다. 이메일 인증은 활성화되어 있습니다.

## 실행과 배포
Node.js 24에서 `npm ci`, `npm test`, `npm run build`를 실행합니다. `npm run dev`는 로컬 개발 서버입니다.
GitHub Pages에 실행 파일을 올릴 경우 dist의 내용을 배포합니다. 원본 소스를 저장소에 올릴 경우 포함된 .github/workflows/pages.yml을 사용하고 Pages Source를 GitHub Actions로 변경합니다.

Supabase 프로젝트: uvzxyrbyszvmnlxchvoc (서울). 기본 공개 URL과 publishable key는 src/supabase.ts에 있습니다. VITE_SUPABASE_URL / VITE_SUPABASE_PUBLISHABLE_KEY로 재정의할 수 있습니다. 공개 키는 비밀번호가 아니며 각 사용자의 데이터 접근은 데이터베이스 RLS로 제한합니다. service_role, secret key, 메일 비밀번호는 클라이언트나 GitHub에 넣지 마세요.

Site URL과 허용 Redirect URL은 위 GitHub Pages 주소로 설정했습니다. 로컬에서 이메일 링크까지 테스트하려면 로컬 주소도 Supabase에 명시적으로 추가해야 합니다.

## 저장과 검증
supabase/001_portfolios.sql에 테이블과 소유자별 접근 정책이 있습니다. 현재 프로젝트에는 이미 적용했으므로 재실행하지 마세요. 기록 전체 삭제는 계정의 기록 내용을 비우며 회원 계정 자체는 삭제하지 않습니다.

로드맵·인증·파일·상세 페이지·로그인 접근 제어 테스트 총 56개가 포함됩니다. 인증 테스트는 계정 전환, 늦게 도착한 조회·저장 응답, 로그아웃, 게스트 기록 분리, 조회 실패 시 덮어쓰기 방지를 검사합니다. 실제 데이터베이스에서 다른 계정의 조회·수정·삭제·삽입 차단과 비로그인 접근 차단을 검사했으며 테스트 데이터는 트랜잭션 롤백했습니다.

실제 회원가입과 인증 링크, 비밀번호 재설정의 사용자 확인이 필요합니다.
기존 미션형 로드맵은 AI 활동 추천으로 대체했습니다. 실제 분석에는 서버 OPENAI_API_KEY 설정이 필요합니다. 기관 인증은 아직 연결되지 않았습니다. SBT는 Sepolia 테스트넷에 배포되어 본인 기록 배지를 발급·검증·취소할 수 있습니다. 이용자의 MetaMask 연결과 Sepolia 테스트 ETH가 필요합니다.


## 2026-11-02 인증 개선

신규 비밀번호와 재설정 비밀번호는 10~128자이며 영문 대문자·소문자·숫자·특수문자를 모두 포함해야 합니다. 확인란의 일치 여부를 검사합니다. 서버에도 최소 10자 및 네 종류 필수 정책을 적용했습니다. 기존 계정 로그인에는 새 규칙을 소급하지 않습니다.

인증 링크의 만료·실패 및 성공 결과를 표시합니다. 가입 후 인증번호 입력 화면으로 이동하며 인증 메일 재발송과 60초 대기를 지원합니다. 인증 메일에는 링크와 6자리 인증번호가 함께 포함됩니다. 재발송 후 가장 최근 메일을 사용하세요. 다른 브라우저에서 인증했다면 원래 브라우저에서는 로그인하면 됩니다. 실제 메일로 인증 완료 여부는 사용자 확인이 필요합니다.

## 활동 결과물 파일

로그인한 계정의 새 활동 및 기존 활동에 파일을 첨부할 수 있습니다. 활동당 최대 5개, 파일당 10MB. 사진, PDF, TXT/CSV, DOCX/PPTX/XLSX, HWP/HWPX, ZIP, MP4/MP3를 지원합니다. `activity-files` 버킷은 비공개이며 auth.uid()와 파일 경로 소유자가 같은 계정만 업로드·다운로드·삭제할 수 있습니다. 파일명은 별도 메타데이터로 보관하고 저장 경로는 UUID를 사용합니다. 서비스 비밀 키는 클라이언트에 없습니다.

게스트 사용은 제공하지 않습니다. 기존 브라우저의 게스트 기록은 새 버전 실행 시 삭제합니다. JSON 백업에는 첨부파일 원본이 포함되지 않습니다. 파일은 개별 내려받기로 백업합니다. 기록 교체·삭제 시 해당 계정의 더 이상 참조하지 않는 파일도 정리합니다. 삭제한 파일은 JSON만으로 복구할 수 없습니다. 활동 첨부파일은 SBT 해시 검증 대상이 아니며 검증 파일에 파일 저장 경로를 넣지 않습니다.

저장소 스키마는 supabase/migrations/20261102063711_private_activity_file_storage.sql에 기록했습니다. 첨부 개수 제한은 화면 검증이며 저장소의 파일당 크기·종류 제한과 소유자 접근 규칙은 서버에서도 적용됩니다. 프로젝트 총 저장 용량은 운영 중 모니터링해야 합니다.

## 활동 상세 페이지와 수정

활동 목록·최근 활동·포트폴리오의 활동 제목을 누르면 `?tab=activities&activity=<id>` 고유 주소로 상세 페이지를 엽니다. 새로고침·뒤로 가기를 지원하며 현재 로그인 계정의 기록만 조회합니다. 상세 페이지에서 제목·유형·날짜·기관·내용을 수정하고 기존 첨부파일을 관리합니다. 저장 실패 시 입력을 유지하며 저장하지 않은 내용의 이동·닫기를 경고합니다. 기록 수정은 이미 발급된 SBT를 변경하지 않습니다.

## 활동 링크 공개와 첨부파일 선택 공개

활동 상세의 ‘공개 및 링크 공유’에서 비공개 또는 링크 공개를 선택하고 설정을 저장합니다. 처음에는 비공개이며 첨부파일은 모두 미선택입니다. 공개한 활동 하나의 제목·유형·날짜·기관·내용과 체크한 파일만 읽기 전용 링크에서 로그인 없이 확인할 수 있습니다. 일반 앱 이용에는 계속 로그인이 필요합니다.

공유 테이블 activity_shares는 소유자만 관리하고 익명 목록 조회는 금지합니다. 공개 조회는 activity-share Edge Function에서 추측하기 어려운 개별 토큰을 확인한 뒤 필드를 제한합니다. 비공개 첨부의 이름·경로, 계정 식별자·이메일 및 다른 활동은 응답하지 않습니다. 파일 다운로드마다 토큰·선택 목록·원본 활동·소유자 경로를 재검증하며 공개 URL/장기 서명 URL을 만들지 않고 no-store 응답으로 전달합니다. 서비스 키는 Edge Function 환경에서만 사용합니다. verify_jwt=false는 비로그인 공유 수신자를 위한 것이며, 본문 내 공유 토큰과 공개 파일 선택으로 접근을 확인합니다.

활동 삭제/가져오기 교체로 사라진 활동의 링크는 DB 트리거로 폐기됩니다. 비공개 전환은 공유 행을 제거하며 다시 공개할 때 새 토큰을 만듭니다. 공유 내용은 최신 저장 기록이며 열린 공유 페이지는 30초 간격으로 재확인합니다. 이미 내려받거나 복사한 자료는 회수할 수 없습니다. 검색 제외 메타 태그를 넣지만 링크 소지자의 재공유를 막는 기능은 아닙니다.

검증: 공개 응답의 필드·파일 허용 목록, 기본 비공개/미선택, 비공개 복귀 테스트; 실제 DB의 소유자 조회·타 계정 차단·활동 삭제 시 링크 폐기(롤백); 익명 목록 접근 거부와 존재하지 않는 토큰 404 및 no-store 응답 확인.


## 활동 기반 AI 추천 (2026-11-02)

`?tab=recommendations`에서 본인이 저장한 기록을 바탕으로 관심 주제·추천 이유·다음 활동·실행 단계·돌아볼 질문을 제안합니다. 근거 기록을 누르면 상세 페이지로 이동합니다. 기존 `?tab=roadmap` 링크는 새 화면으로 연결하며, 이전 백업 파일 호환성은 유지합니다. 첨부파일과 프로필·계정 정보는 AI에 보내지 않습니다. 제목·유형·날짜·본문 중 최근 30개, 본문당 최대 1,500자를 사용합니다.

운영자 최초 연결:
1. https://platform.openai.com/ 에서 API 계정을 준비하고 결제/사용량 설정을 확인합니다. 사용자가 직접 진행해야 합니다.
2. 프로젝트 API 키를 발급합니다. 키를 채팅이나 GitHub에 올리지 마세요.
3. https://supabase.com/dashboard/project/uvzxyrbyszvmnlxchvoc/functions/secrets 에서 이름 `OPENAI_API_KEY`, 값은 발급한 키로 저장합니다.
4. 선택적으로 `OPENAI_MODEL`을 설정할 수 있습니다. 기본 모델은 `gpt-4.1-mini`이며 Responses API와 strict JSON schema를 지원해야 합니다.
5. 사이트 로그인 → AI 활동 추천 → 전송 동의 → 추천 받기로 실제 응답을 확인합니다.

`activity-recommendations` 함수는 이미 배포했습니다. 키가 없으면 연결 준비 중 메시지를 표시하며 가짜 추천을 만들지 않습니다. 모델 응답은 store:false로 요청합니다. 인증 사용자 getUser 검증과 본인 portfolio RLS 조회 후 서버에서만 API를 호출합니다. gateway verify_jwt=false 대신 함수 본문에서 JWT를 검증하므로 비로그인 요청은 401입니다. 별도 service-only 테이블에서 요청 간 1분/UTC 하루 5회 제한, 변경 없는 기록의 결과 재사용, 동시 요청 잠금을 적용합니다. 모델이 반환한 존재하지 않는 근거 기록은 거절합니다. 실제 AI 응답 검증은 키 연결 후에 완료할 수 있습니다.


수정 가능한 소스는 pathfolio-source.zip에 들어 있습니다. 현재 저장소는 실행 파일 배포 방식(main / root)입니다.
